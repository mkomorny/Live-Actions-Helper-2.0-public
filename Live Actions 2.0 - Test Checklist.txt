LIVE ACTIONS HELPER 2.0 -- HANDS-ON TEST CHECKLIST (after the redesign)
========================================================================
Written for v1.0.66.  Covers ONLY what the automated suites cannot prove.


WHAT THIS IS
------------
The WebView2 redesign ("Layout A Workbench") is feature-complete and every
automated check passes -- 416 unit tests, 199/199 end-to-end, 12/12 instance
checks, 12/12 Breakdowns theme-persistence checks, and per-kit screenshot
fidelity of 0.00-0.18% against a 2% limit.

All of that ran against a MOCK Ableton and a MOCK language model.  Nothing in
this app has ever touched real Ableton, a real API key, the real Cartesia
network, or the real installer.  That gap is what this document tests.

Already proven by automation -- DO NOT re-test by hand:
  * the theme picker's mechanics, every kit's layout integrity, and the shell's
    own theme surviving a restart
  * every Preferences control as a real round trip, with settings.json read
    back as the source of truth
  * the slot picker's logic, the overwrite confirm, Escape/cancel, and the
    native Save As being driven for real
  * the three dialogs opening, being driven through their own buttons, and
    Cancel/X writing nothing
  * Launch Live Actions.bat starting the shell, the liveactions:// argument,
    and the preflight message box
  * Genius streaming, tool-call chips, Stop closing the turn, and the markdown
    escaping


HOW TO USE IT
-------------
1. Save your own copy (e.g. "Live Actions 2.0 - Test Checklist FILLED IN.txt")
   and type into that one, so the blank original stays blank.
2. Work top to bottom.  Section A needs nothing but the PC.  Section B onwards
   needs Ableton Live 12 open with the Live Actions Bridge device loaded.
3. Under each item, replace the RESULT line with one of:
      PASS
      FAIL: <exactly what you saw>
      SKIP: <why>
   For Genius items, paste the model's FULL raw reply, not a summary.
4. Replace anything in [BRACKETS] with the real track / slot / clip from your
   Set before you send it.
5. Errors are data.  If something errors or refuses, paste that too.
6. Screenshots help for anything visual -- save them beside this file and write
   the filename in the RESULT block.

Track numbers are always "as Live shows them" (1-based), per the app's own
convention.

When you are done, send the filled-in file back and it gets triaged the same
way as last time: confirmed, new findings, and anything needing more data.

SECTION 0 -- BEFORE YOU START  (read this, it prevents false failures)
========================================================================

0a. USE THE RIGHT LAUNCHER.  In
    C:\Users\<you>\My Apps\Live Actions Helper Redesign
    double-click:

        Launch Live Actions.bat          <-- USE THIS ONE

    Do NOT use "Launch Redesign Shell.bat" for any test in this document.
    That one runs the app as the isolated "redesign" instance: it listens on
    UDP 12025/12024 instead of 11925/11924, and the Max device only ever talks
    to 11925/11924.  It also has its own empty settings file, so it has none of
    your API keys.  Testing with it would give you a permanently offline dot,
    an empty track list and "no API key" -- none of which would be real bugs.

0b. ONLY ONE AT A TIME.  The new shell and the classic Tk app share one
    single-instance lock.  If one is already running, launching the other just
    raises the first window instead of opening a second.  Quit the Tk app
    before you start.

0c. SAME SETTINGS FILE.  The shell reads and writes the same
    %APPDATA%\Live Actions\settings.json as the Tk app -- your real keys,
    folders and TTS profiles are already there.  Anything you change in the
    shell's Preferences also changes it for the Tk app.  That is intended.

0d. USE A THROWAWAY SET with at least one AUDIO track and one MIDI track, and
    a few clips you do not mind renaming, recolouring or overwriting.  Several
    tests write into your Set.

0e. WHAT THE WINDOW LOOKS LIKE.  Top bar: "Live Actions", the tabs Actions and
    Genius, a connection dot that reads Online / Offline, and a gear icon
    (Preferences).  Left column: Live Set card and Target tracks.  Middle:
    Studio Actions cards.  Right: the inspector for whichever action you click.
    Bottom: a status bar with Copy, Console log and Thinking log (Thinking log
    lists what Genius reasoned and which actions it ran; v1.9.0).

# Live Actions

Desktop host for **Ableton Live 12 Standard + Max for Live**. It is a homemade stand-in for Suite-only Extensions: a window on the PC plus a Max for Live bridge in the Set.

This is not official Ableton Extensions and not official Producer Pal.

## What you get

- **Actions** — talks to Live over localhost OSC (ports 11924 / 11925). Tools: Breakdowns, Clip Namer, Arrangement Skeleton, Mutate, Empty / Color / Duplicate Clips, Track Batch, Reveal Device, Detect Key, BBenCut.
- **TTS Vocal** — generates an AI text-to-speech WAV from typed text via a saved provider profile (OpenAI, xAI, or Cartesia), with per-run voice/speed/language overrides. Runs on the desktop host itself, not through the Max bridge — see `tools/tts-vocal` and `app/tts_vocal.py`. Profiles are managed in Settings → TTS Vocal Profiles (collapsible cards), with a "Detect provider" button that identifies OpenAI/xAI/Cartesia/ElevenLabs from a pasted API key, a "or use saved key…" picker that pulls from the same Saved API Keys vault instead of re-pasting one, and a "↻ Refresh voices" dropdown that lists built-in and cloned voices together (cloned voices ★-starred and sorted first). Check a profile's box to **pin it as the only voice** (v1.5.0) — every generation, from the Tool screen or from Genius, is then locked to that exact voice; no other saved profile and no per-run voice override can be used until it's unchecked. Supports voice cloning on both xAI and Cartesia: clone a voice for free in the provider's console, paste the Voice ID in, and generate with it like any other voice. Cartesia bills roughly 1 credit per character generated. Save the result to a folder you pick, or place it straight into a ticked audio track's Live Set with a non-destructive slot picker.
- **Audio Sample** — ffmpeg-backed sample prep: trim/fades/levels, convert, reverse/pitch-time, six effects, three generators (17 operations in one tool screen). Runs on the desktop host, not through the Max bridge — see `tools/audio-sample` and `app/audio_sample/`. Output folder defaults to `<Ableton Samples Folder>\Audio Samples`, configurable in Settings alongside the shared ffmpeg path.
- **Settings** — Saved API Keys vault (xAI, Google Gemini, Anthropic Claude, or OpenAI — paste a key, detect its provider, save it, switch between saved keys), an editable AI Model dropdown that refreshes from the active key's provider, tools folder, Knowledgebase Library folder, Ableton Samples folder
- **Genius** — Producer Pal–parity Live control through the Live Actions Bridge, plus the copied Genius library (INDEX + books), audio analysis suite ("Ears": integrated LUFS, true peak dBTP, 10-band spectrum, brightness, punch, stereo width, A/B comparison), DirectShow loopback audio recording, VU/peak metering, Rack macro controls, surgical note removal, Arrangement timeline clip duplication, inspection, editing, note read/write/removal, clip movement, and song length, Deep Take Lane Management (inspect, rename, create clips), Transport Shortcuts (undo, redo, playhead jump-to-time, overdub, capture MIDI, back to arranger, re-enable automation, crossfader, folding, groove pool, loop doubling), Algorithmic MIDI Generators (Euclidean rhythms, voiced chord progressions, walking bass, motif inversion/retrograde, ASCII drum grids), Offline .als Project Tools (summary, track/clip inspection, MIDI extraction, version diffing, unfinished work linter), Heuristic Mix Checker (clashing low-end, panning, headroom, limiter protection), Multi-Track Batching, clip launch/warp modes, transport scrubbing, Drum Rack pads, GUI view focus, Session Snapshot & Verification Diff Loop, Declarative 14-Recipe Genre Engine, Deep Plugin Inspection, 1-Shot GUI Selection Reader (`live_get_selected`), In-Clip Automation Envelope Reset (`live_clear_clip_envelopes`), High-Level Step-String Drum Engine (`live_create_drum_pattern`), Roman Numeral Chord Progression Engine (`live_create_chord_progression`), Unified Track/Clip/Scene Editing (`live_edit_*`), Rack Magnitude Mapping (`live_map_rack_magnitude`, v1.0.23), Live-visible VST/AU parameter read/write on already-present plugins (v1.0.24), and Complete Clip Lifecycle & Automation Suite (`live_set_clip_follow_action`, `live_get_clip_follow_action`, `live_set_clip_launch_mode`, `live_set_clip_fades`, `live_set_clip_markers`, `live_manage_warp_markers`, `live_set_clip_automation`, `live_get_clip_automation`, `live_add_shaped_automation`, `live_commit_groove`, note probability & velocity deviation, and relative device shifting, expanding the suite to 108 tools in v1.0.25), and Name-Based Track Addressing (an optional `track_name` alongside `track_number` on the highest-traffic track tools, resolved bridge-side by exact/substring match against the live Set, so Genius no longer has to guess an index from what you typed; v1.0.28). The Genius chat panel shows a read-only **SESSION TRACKS** list (mixer number, name, devices) instead of the Actions tab's TARGET TRACKS picker, since Genius resolves tracks itself rather than reading ticked state; Enter sends the message (Shift+Enter for a newline). Genius's knowledge search (`library_db_search`) covers 16 structured topics in the Music/Audio database (added M4L general, Music Production, and Surge in v1.0.29); the TRAINING DOCS library is an explicit last resort behind that database, not a co-equal first stop. Every position Genius takes or reports (`track_number`, `slot_number`, `scene_number`, `device_number`, `clip_number`...) is exactly what Live's own UI shows — Live's track 1 is `track_number` 1, never a 0-based index — with recipes gated behind a `requires` flag when they need browser/preset access this app doesn't have yet (v1.0.32). An offline LOM truth table (`app/lom_reference.py` / `app/lom_surface.json`, parsed from a runtime-introspected Live 12.3.6 reference) now checks every `.get`/`.set`/`.call` literal the bridge sends against real LOM members before a new action ships, catching a defect at authoring time instead of in a live session; it added 14 verified tools (`live_set_loop_region`, `live_set_groove_amount`, `live_nudge`, `live_set_swing`, `live_set_appointed_device`, `live_set_automation_record`, `live_read_param_range`, `live_set_param_raw`, `live_show_message`, `live_read_dialog`, `live_read_cpu`, `live_view_control`, `live_read_selected_notes`, `live_transform_selected_notes`) and fixed a silent `live_version=""` bug and a silent-success bug in `live_update_device`, bringing the suite to 122 tools (v1.0.39). Selectable **Genius Agents** (v1.0.42): a chat top-bar
switcher lets you swap the stock Genius persona for a specialist — Mix & Master Engineer, Music
Theory & Harmony, Sound Designer / Synthesist, or Drum & Beat Programmer — each with its own
persona paragraph and a per-agent, per-tool on/off list (Settings → AI Model → Agent) that
persists across restarts; `live_connect` / `live_read_set` / `live_context` are always sent
regardless of an agent's toggles. A disabled tool is refused if the model calls it anyway, not just
left off the offered list (v1.0.43), and a long multi-track ask always ends in a real answer instead
of erroring out at the tool-call limit (v1.0.43). Agents are enabled once from Settings, then live in
the switcher permanently; drop a new persona `.md` file in `%APPDATA%\Live Actions\personas\` to add
one without touching the repo.
- **Genius can generate and edit audio (v1.2.0)** — the TTS Vocal and Audio Sample pipelines above were previously reachable only from the Tool screen; Genius can now run them itself. `live_tts_vocal` generates a spoken WAV from your saved TTS profile, and `live_audio_op` runs any of the 17 ffmpeg operations on a file (call it with no operation and it lists them all with their real field names). Two things it is made to be honest about: TTS models **speak, they do not sing**, and the length of a generation is a *result* of the text and speed, not a setting — so it quotes the duration that actually came back and uses `trim` if you want an exact length. Because generating bills your own API key, **the app asks you to approve each call** in a modal that shows the profile, voice and exact text, with a "don't ask again this session" box (session-only, never written to settings). Decline and Genius reports it rather than retrying. The finished file reaches Live through a new `sample` param on `live_update_device` / `live_create_device`, which loads it into a **Simpler** on any track (Simpler only — `replace_sample` has no Sampler equivalent in the API), or as an audio clip via `live_create_clip`. Genius reads your running Live version itself (v1.3.0) and states whether `replace_sample` exists in your build instead of asserting a fixed version requirement; if a load doesn't verifiably land, the bridge reads the device's own sample back and reports the real reason rather than guessing. With no TTS profile saved, `live_tts_vocal` is withheld from the model entirely and Genius says to add one in Preferences → TTS Vocal Profiles.
- **Pin a TTS profile as the only voice (v1.5.0)** — checking a profile's box in Settings → TTS Vocal Profiles locks every generation to that exact voice, in both the Tool screen and Genius. Genius is told which profile is pinned right in the system prompt and refuses (with an error naming the pin) rather than silently switching if asked for a different one; a per-run `voice` override is dropped the same way, since a lock with a loophole isn't a lock. Renaming the pinned profile keeps the pin; removing it clears the pin rather than pointing at nothing.
- **Genius stops guessing about Live's version (v1.3.0)** — `live_connect` now surfaces the running Ableton build, and Genius states it unprompted instead of asserting a fixed version requirement or asking you what version you have. A version-gated capability (loading a sample into a Simpler, `replace_sample`, Live 12.4+) is reported as a resolved fact about *your* build; when the version hasn't been read yet, Genius tries the action and reports what actually happened rather than refusing on a guess. If a sample load doesn't verifiably land, the bridge reads the device's own sample back and names the real reason instead of a canned "drag it in by hand." Also fixed: a device-update failure that had no `error` field was being displayed under the success message text (`ERROR: Updated device 'Simpler'`); stale "Pal cannot write automation / add VST-AU" claims in the Genius library index no longer contradict what the tools actually do; and a stopped/failed turn is now recorded in Genius's own conversation history as a neutral note rather than something Genius said, so it doesn't read its own past turns as a string of abandonments.
- **Live browser access (engine E2, v1.1.0)** — Genius can read and load from Live's own library panel: `live_browse` walks the tree (Sounds, Drums, Instruments, Audio/MIDI Effects, Max for Live, Plug-ins, Clips, Samples, User Library, Packs), `live_load_browser_item` drops a preset, rack, native device or VST/VST3 onto a track, and `live_preview_browser_item` auditions one without touching the Set. `live_library` search and `listPlugins` return real browser hits and real installed plug-ins instead of the old empty stubs. This cannot run through the Max for Live bridge — `Application.browser` is not in the M4L LOM at all — so it ships as a small companion Remote Script, `remote_script/LiveActionsRS`, installed by `install.ps1` to `A:\User Library\Remote Scripts\LiveActionsRS` and reached over TCP 11926. **It needs one manual step:** in Live, Preferences → Link/Tempo/MIDI → any free Control Surface slot → `LiveActionsRS`, then restart Live. Everything degrades cleanly without it: the browser tools are withheld from the model, and Genius says browser access is unavailable rather than promising it.
- **Thinking from Gemini and Claude (v1.12.0)** — with **Show thinking** ticked, Genius now asks Gemini (2.5 and later) and Claude (3.7 and later) models to send their reasoning, so it appears in the Thinking fold-out the way Grok's does. Untick the box and the request goes out without the ask. Note that Claude Opus 4.7 / 4.8 and Claude 4.5-and-earlier models did not think at all before, so they use more output tokens with the box ticked.
- **Show thinking, and rename saved keys (v1.11.0)** — a **Show thinking** checkbox beside the model picker turns the model's reasoning on or off inside Genius's replies (the Thinking log drawer always keeps it). It appears only for reasoning models, or once a model has actually streamed reasoning. In Preferences → AI provider, the pencil on a key row renames that key.
- **Separate key and model pickers, keys grouped by provider (v1.10.0)** — the Genius chat header has one dropdown for your saved keys (names only, grouped by provider) and a second for the model, which lists only the models that work for the key in use. In Preferences → AI provider, keys are folded under one heading per provider and the Model box for the current key is always visible. The custom-instructions dropdown ends with **+ New Custom Instructions…**, which opens a small dialog so you can write a preset without leaving the chat; it stays in the list until you delete it in Preferences.
- **Switch API key and model from the chat (v1.8.0)** — the dropdown at the top of the Genius chat lists every saved key with only the models that actually work for it. At launch, each key's chat models are fetched and sent one tiny test message (with a tool, since Genius needs tool calling). Models that fail are hidden: no access, retired, or not a chat model (Live, Lyria, TTS, image, video, embedding). Models that are only overloaded or rate-limited stay in the list, marked "(busy)". Picking one switches key and model at once, sets that provider's correct endpoint, and posts a "Now using …" line. It can't change mid-reply. Preferences → Model & endpoint has the same dropdown. When a provider is overloaded (503) or a key hits its limit (429), Genius says so in one plain sentence instead of the raw error.
- **Genius custom instructions (v1.1.0)** — your own standing instructions for how Genius answers (length, tone, what to always mention). Saved as named presets that are reusable across projects, while the preset actually in use is remembered **per Live Set**. Switch it from the dropdown beside the agent picker in the chat, or manage presets in Preferences → Genius custom instructions. Genius will append an instruction when you ask it to remember one, and tells you exactly what it added; it cannot delete your instructions, and only ever removes a line when a new instruction directly contradicts it — saying so when it does.
- **Themes** (the WebView2 window) — eleven design kits, picked in Preferences → Appearance (collapsed by default; Riso Art Studio is the opening theme). Each kit's fonts are bundled, so every theme looks right offline. Breakdowns keeps its own look and its own theme picker, which now remembers your choice between runs.
- **Live Actions** — Max for Live audio effect you drop on a track. Audio passes through.
- **App Changes Tracker.html** — version log for every shipped change (this folder, next to this README)
- **Live Actions 2.0 - Test Checklist.txt** — the hands-on checklist for the WebView2 redesign (this folder): everything the automated suites cannot prove — real Ableton, real keys, the real Cartesia call, the eleven kits by eye, and the installer. Use `Launch Live Actions.bat` for it, not `Launch Redesign Shell.bat` (that one runs on offset UDP ports and cannot see the Max device).

Official Producer Pal files are not in this repo and must not be patched from here.

## Requirements

- Windows
- Python 3, plus `python -m pip install -r requirements.txt` (pywebview + pythonnet for the window)
- The Microsoft Edge WebView2 Runtime (already on current Windows 10/11; the app tells you if it is missing)
- Ableton Live 12 Standard with Max for Live
- An AI API key ([xAI](https://console.x.ai), [Google AI Studio](https://aistudio.google.com), [Anthropic](https://console.anthropic.com), or [OpenAI](https://platform.openai.com)) if you use the Genius tab

## Start

1. Run `install.ps1` to copy the bridge into the User Library and put a Desktop shortcut down. It also pings the device already in your Set (if any) and tells you whether it's running this build or needs a re-drop.
2. In Live, drop **Live Actions** on an audio track (User Library → Audio Effects → Max Audio Effect). Audio passes through.
3. Click **Open desktop host** on the device, or double-click **Live Actions** / `Launch Live Actions.bat`. The window resizes down to 720×520, so it can sit in a narrow strip beside Ableton.
4. Wait for **Connected**, then open **Settings** and set:
   - xAI API key
   - **Knowledgebase Library folder** (defaults to `B:\Documents\TRAINING DOCS`) — third-party plugin manuals, official Live PDF
   - **Music/Audio Database** (defaults to `B:\AI Directories_Databases\datasets\Music_Audio`) — Genius's preferred, full-text-searchable source for everything else (Live, theory, sound design, Novation, drum pads, DSP…)
   - **Ableton Samples folder** (defaults to `A:\User Library\Samples`)

5. Optional, for Live-browser access: in Live, Preferences → Link/Tempo/MIDI → any free **Control Surface** slot → **LiveActionsRS**, then restart Live. `install.ps1` copies the script and reports whether it is answering. Skip this and everything else still works; only the browser/preset/plug-in tools stay off.

Full desk steps: `HOW-TO-START.txt`.  
How the host works and how to add a tool: `APP-DETAILS.txt`.

## Layout

```
app/                 desktop window (Python)
app/genius/          copy of Producer Pal Genius, bundled in the app — originals were not modified
app/genius/personas/ selectable Genius agent files (persona + per-tool defaults)
bridge/              Max for Live OSC bridge
tools/               tool cards (Breakdowns, BBenCut are live; others are shells)
install.ps1
Launch Live Actions.bat
```

Settings are stored in `%APPDATA%\Live Actions\settings.json`, not in this repo.
